# Pi0 / Flow Matching 学习问题记录

## 1. Beta 分布随机采样是什么？

问题：Beta(1.5, 1.0) 为什么可以得到 `[0, 1]` 的值？

记录：Beta 分布的取值范围固定在 `[0, 1]`（连续分布严格采到端点的概率为 0）。`alpha=1.5` 和 `beta=1.0` 是形状参数，不是范围参数。Beta(1.5, 1.0) 的密度为：

```text
f(x) = 1.5 * sqrt(x), 0 < x < 1
```

它更偏向较大的值，均值为 `1.5 / (1.5 + 1.0) = 0.6`。

## 2. 概率密度为什么可以大于 1？

问题：`f(0.99) = 1.5 * sqrt(0.99) > 1`，这是否矛盾？

记录：`f(x)` 是概率密度，不是单点概率。连续变量取到某个精确值的概率为 0，区间概率通过积分得到：

```text
P(a < X < b) = integral(f(x), a, b)
```

概率密度可以大于 1，要求是整个区间下的面积等于 1：

```text
integral(1.5 * sqrt(x), 0, 1) = 1
```

## 3. Flow Matching 中的时间采样

配置：

```python
time_sampling_beta_alpha = 1.5
time_sampling_beta_beta = 1.0
time_sampling_scale = 0.999
time_sampling_offset = 0.001
```

先采样：

```text
z ~ Beta(1.5, 1.0)
```

再变换为：

```text
t = 0.999 * z + 0.001
```

因此 `t` 约位于 `(0.001, 1.0)`。例如 `z=0.4` 时：

```text
t = 0.4 * 0.999 + 0.001 = 0.4006
```

`t` 越接近 0，带噪动作越接近真实动作；`t` 越接近 1，越接近随机噪声。

## 4. `None` 参数是什么意思？

问题：`action_feature_names = None` 中的 `None` 有什么意义？

记录：

```python
action_feature_names: list[str] | None = None
```

表示该变量允许是动作名称列表，也允许暂时没有值。这里的 `None` 表示“尚未从数据集元数据填充”，不是字符串。它与空列表 `[]` 不同：`None` 表示未设置，`[]` 表示已设置但元素数量为 0。

## 5. `rtc_config = None` 的含义

问题：`rtc_config: RTCConfig | None = None` 是什么？

记录：RTC 是 Real-Time Chunking，用于实时执行时衔接新旧动作块。默认 `None` 表示不启用这项可选功能；设置为 `RTCConfig(...)` 后才使用相关动作块融合配置。

## 6. 图像为什么要统一成固定尺寸？

问题：原始图像变成 `224 x 224` 是直接裁剪吗？全局相机不能裁剪怎么办？

记录：固定尺寸不代表一定采用裁剪，常见预处理包括直接缩放、中心裁剪、等比例缩放加 padding。全局相机通常使用等比例缩放加 padding，以保留完整视野；局部相机可以适度裁剪突出操作区域。不同相机可以使用不同策略，但最终输入视觉编码器的 Tensor 形状通常要一致。

## 7. 是否不建议更改输入图像尺寸？

记录：使用预训练 Pi0/PaliGemma 时，不建议随意更改最终输入尺寸，因为可能改变预训练分布、视觉 token 数量、位置编码匹配关系，并增加显存和计算量。通常保持模型预期尺寸，使用缩放、padding 和相机特定裁剪策略。若要改分辨率，应确认视觉编码器支持，并同步处理位置编码、预处理和训练配置。

## 8. `tokenizer_max_length` 是否也不能修改？

问题：`tokenizer_max_length=48` 是否像图像输入尺寸一样，基本不能修改？

记录：可以修改，但不建议没有需求就随意修改。文本最大长度通常比图像分辨率更容易调整，因为它主要改变文本 token 数量，而不是图像 patch 网格。调大前需要确认模型总上下文长度、位置编码、图像 token 与文本 token 的总长度限制以及显存是否允许；调小则可能截断指令。对于当前 Pi0 配置，普通机器人指令能在 48 个 token 内表达时，优先保留默认值。只有指令经常被截断时，才考虑适度调大并重新验证训练和推理。

## 9. 什么是字典、键和值？

问题：`normalization_mapping` 为什么是字典，字典的键是什么意思？

记录：字典是按照“键 -> 值”保存对应关系的 Python 容器。例如 `{"STATE": NormalizationMode.MEAN_STD}` 中，`"STATE"` 是用于查找的键，`NormalizationMode.MEAN_STD` 是对应值。`dict[str, NormalizationMode]` 表示键必须是字符串，值应为 `NormalizationMode`。字典是可变对象，因此 dataclass 使用 `field(default_factory=lambda: {...})` 为每个配置实例创建独立字典，避免实例间共享修改。

## 10. 冻结视觉编码器后为什么还要输入图片？

问题：视觉参数不更新时，提取视觉信息还有什么意义，模型如何知道要抓哪个物体？

记录：冻结参数不等于不使用模块。每张图片仍通过视觉编码器产生不同视觉特征，动作专家学习把这些特征映射为动作。预训练视觉语言模型已经具备物体、颜色和语言对齐能力时，可以冻结它并只学习如何操作；若相机类型、场景或目标物与预训练分布差异很大，则可能需要解冻视觉编码器。是否更新视觉参数可以近似理解为是否根据新数据调整物体的视觉表示，但不是修改一条显式的物体定义。

## 11. Transformer 在哪个模块，参数是否在其中更新？

问题：数据流中为什么没有单独画 Transformer，参数更新是否发生在 Transformer 层？

记录：Transformer 包含在 PaliGemma 和 Gemma Action Expert 内部，不是并列的第三个模型。源码通过 `paligemma.model.language_model.layers` 和 `gemma_expert.model.layers` 取得两组 Transformer 层，并在 `compute_layer_complete()` 中执行 LayerNorm、QKV、Attention、MLP 和残差连接。前向传播产生 loss，`loss.backward()` 计算所有未冻结参数的梯度，`optimizer.step()` 才真正更新包括 Transformer 在内的参数。

## 12. `sample_beta()` 是否在数据集中取样？

问题：Beta 采样与数据加载之间是什么关系？

记录：不是从数据集中抽取样本。DataLoader 先取得图像、语言、state 和真实 action 组成 batch；程序再为每条 action 随机生成 noise，并通过 `sample_beta()` 为每条样本独立生成噪声时间 `t`。随后使用 `x_t = t * noise + (1-t) * action` 构造模型输入。

## 13. `modeling_pi0.py` 前几个辅助项是什么关系？

记录：`ActionSelectKwargs` 只描述推理和 RTC 可选参数的字典格式；`sample_beta()` 为每条训练样本生成标量时间 `t`；`create_sinusoidal_pos_embedding()` 将标量 `t` 编码为 Action Expert 可使用的高维向量；`get_safe_dtype()` 被时间编码函数调用，用于选择当前硬件兼容的浮点类型。当前学习策略调整为先掌握模块职责和调用位置，再结合实际调用学习局部公式。
