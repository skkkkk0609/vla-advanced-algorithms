创建对象时，模型得到这些子模块：

```text
NeuralNetwork
├── flatten
└── linear_relu_stack
    ├── Linear(784, 512)
    ├── ReLU
    ├── Linear(512, 512)
    ├── ReLU
    └── Linear(512, 10)
```

调用：

```python
logits = model(X)
```

不要理解成普通变量调用。因为 `model` 继承了 `nn.Module`，所以它是一个**可调用对象**。简化流程是：

```text
model(X)
  -> nn.Module.__call__(X)
  -> 执行 PyTorch hooks 等内部逻辑
  -> model.forward(X)
  -> 返回 logits
```

`forward` 中的数据流：

```python
def forward(self, x):
    x = self.flatten(x)
    logits = self.linear_relu_stack(x)
    return logits
```

这里的 `self` 是当前 `model` 对象；`x` 是传入的 `X`。

假设：

```text
X.shape = [32, 28, 28]
```

则：

```text
x = self.flatten(x)             -> [32, 784]
self.linear_relu_stack(x)       -> [32, 10]
return logits                   -> [32, 10]
```

关键区别：

- `__init__`：定义模型**拥有哪些层和参数**。
- `forward`：定义数据**如何经过这些层**。
- `model(X)`：正确调用方式。
- `model.forward(X)`：能运行，但绕过 `nn.Module.__call__` 的外围机制，不应直接使用。

```python
x = torch.ones(5)
y = torch.zeros(3)
w = torch.randn(5, 3, requires_grad=True)
b = torch.randn(3, requires_grad=True)
z = torch.matmul(x, w) + b
loss = torch.nn.functional.binary_cross_entropy_with_logits(z, y)
```

**各变量的职责和 shape**

```text
x     [5]       输入特征
w     [5, 3]    权重
x @ w [3]       线性变换结果
b     [3]       偏置
z     [3]       模型的原始输出 logits
y     [3]       目标标签
loss  []        标量损失，即 0 维 Tensor
```

矩阵乘法可理解为：

```text
x [5] @ w [5, 3] -> [3]
```

`x` 的 5 个输入特征经过 `w`，生成 3 个输出；再逐元素加上 `b [3]`，得到 `z [3]`。

**`requires_grad=True`**

训练需要知道“loss 如何随参数变化”，因此给参数设置：

```python
w.requires_grad = True
b.requires_grad = True
```

这表示 PyTorch 要记录涉及 `w`、`b` 的运算，以便随后计算：

```text
∂loss/∂w
∂loss/∂b
```

这里不需要优化输入 `x` 和标签 `y`，所以它们默认是 `requires_grad=False`。

**计算图**

前向计算同时建立依赖关系：

```text
x ─┐
   ├─ matmul ─┐
w ─┘          ├─ add ─> z ─┐
b ────────────┘             ├─ loss function ─> loss
y ──────────────────────────┘
```

## `num_inference_steps`

推理从随机噪声开始，经过 10 次迭代得到动作：

```text
随机噪声 x₁
  ↓ 第 1 次速度预测
x₀.₉
  ↓ 第 2 次速度预测
x₀.₈
  ...
  ↓ 第 10 次速度预测
动作 x₀
```

代码中的步长是：

```text
dt = -1 / 10 = -0.1
```

每一步执行：

```text
x_t = x_t + dt × v_t
```

这里：

- `x_t`：当前带噪动作
- `v_t`：模型预测的变化方向，也叫速度场
- `dt`：时间向 0 移动的步长

`num_inference_steps` 与 `chunk_size` 不同：

- `chunk_size=50`：一次生成多少个时间步的机器人动作
- `num_inference_steps=10`：为了生成整个动作 chunk，进行多少次去噪计算

也就是说：

```text
一个 [B, 50, 32] 的噪声动作块
        ↓ 整体去噪 10 次
一个 [B, 50, 32] 的动作块
```

接着看训练时的时间采样参数：

```python
time_sampling_beta_alpha = 1.5
time_sampling_beta_beta = 1.0
time_sampling_scale = 0.999
time_sampling_offset = 0.001
```

训练时不会固定使用某个噪声程度，而是为 batch 中每个样本采样一个时间 `t`：

```text
t ~ Beta(1.5, 1.0)
t = t × 0.999 + 0.001
```

最终 `t` 大致处于：

```text
0.001 <= t <= 1.0
```

然后构造带噪动作：

```text
x_t = t × noise + (1-t) × action
```

理解两个端点：

```text
t 接近 0：x_t 接近真实 action
t 接近 1：x_t 接近随机 noise
```

例如：

```text
action = 2
noise  = 10
t      = 0.25

x_t = 0.25×10 + 0.75×2
    = 2.5 + 1.5
    = 4
```

模型需要根据 `x_t`、时间 `t`、图像、语言和 state，预测速度目标：

```text
u_t = noise - action
```

在这个例子中：

```text
u_t = 10 - 2 = 8
```

至于：

```python
min_period = 4e-3
max_period = 4.0
```

它们不控制采样范围，而是控制如何把标量时间 `t` 编码成高维正弦/余弦向量：

```text
t [B]
  ↓ sinusoidal embedding
time_embedding [B, expert_width]
```

这与 Transformer 的位置编码思想类似，让模型能区分不同的噪声时间。


## Step 3: `Pi0NewLineProcessor`

在 Pi0 中，状态和自然语言指令简单拼接：


## Step 5: `DeviceProcessorStep`

将所有 Tensor 移动到 `config.device`（通常是 `cuda`）。

## Step 6: `relative_step` (RelativeActionsProcessorStep)

如果 `use_relative_actions=True`，把绝对动作转为相对动作：

```text
action_relative = action - state
```

动作各维名称通过 `action_feature_names` 与 `relative_exclude_joints` 对应的维度跳过转换。

## Step 7: `NormalizerProcessorStep`

基于数据集统计量做标准化：

```text
normalized = (x - mean) / std
```

- `VISUAL`（IDENTITY）：不做标准化
- `STATE`、`ACTION`（MEAN_STD）：做标准化

## 推理后处理

### `UnnormalizerProcessorStep`

将模型输出的标准化动作还原：

```text
raw = normalized * std + mean
```

### `AbsoluteActionsProcessorStep`

如果使用的是相对动作，做反向变换：

```text
absolute = relative + state
```

### `DeviceProcessorStep(device="cpu")`

将结果移回 CPU，以便直接传到机器人控制。

### 1. `create_sinusoidal_pos_embedding` [L85-L102](file:///home/robot/projects/vla-advanced-algorithms/pytorch_learning/lerobot_source/lerobot/policies/pi0/modeling_pi0.py#L85-L102)

把一个标量时间 `t`（形状 `[B]`）转换成一个高维向量，让模型能区分不同的噪声程度。

```python
def create_sinusoidal_pos_embedding(time, dimension, min_period, max_period, device):
```

算法分四步：

**第一步：生成周期数组**

```python
fraction = torch.linspace(0.0, 1.0, dimension // 2, ...)
period = min_period * (max_period / min_period) ** fraction
```

`fraction` 在 `[0, 1]` 内取 `dimension // 2` 个等距点。`period` 是等比缩放：`fraction=0` 得到 `min_period`，`fraction=1` 得到 `max_period`。中间按等比增长。

如果 `dimension=256`，就会有 `128` 个不同的周期，从 `0.004` 到 `4.0`。

**第二步：计算缩放因子**

```python
scaling_factor = 1.0 / period * 2 * math.pi   # shape [128]
```

**第三步：外积得到 `sin_input`**

```python
sin_input = scaling_factor[None, :] * time[:, None]   # [128] × [B, 1] → [B, 128]
```

`time` 从 `[B]` 变为 `[B, 1]`，`scaling_factor` 从 `[128]` 变为 `[1, 128]`，相乘得 `[B, 128]`。

其含义是：对于同一个 batch 样本，时间 `t` 被 `128` 个不同频率的正弦/余弦波同时编码。

**第四步：拼接 sin 和 cos**

```python
return torch.cat([torch.sin(sin_input), torch.cos(sin_input)], dim=1)  # [B, 256]
```

为什么 dim 必须为偶数？因为 sin 和 cos 各占一半。

最终输出 `[B, dimension]`，其中 dimension 应当等于 Expert 的 hidden width（例如 `1024`）。

### 3. `make_att_2d_masks` [L113-L142](file:///home/robot/projects/vla-advanced-algorithms/pytorch_learning/lerobot_source/lerobot/policies/pi0/modeling_pi0.py#L113-L142)

把 padding mask 和 attention mask 合并成最终的 `[B, N, N]` 二维注意力掩码。

**输入：**
- `pad_masks`：`bool[B, N]`，`True` 表示该位置有实际内容，`False` 是 padding
- `att_masks`：`int[B, N]`，控制注意力模式，`1` 处产生新的注意力边界，`0` 表示与前一个 token 属于同一注意力组

**处理：**

```python
cumsum = torch.cumsum(att_masks, dim=1)          # 沿 dim=1 累加，得到每个 token 的组编号
att_2d_masks = cumsum[:, None, :] <= cumsum[:, :, None]  # [B, N, N]
```

假设 `att_masks = [0, 0, 0, 1, 0, 0]`：
- `cumsum = [0, 0, 0, 1, 1, 1]`
- `cumsum[:, None, :]` 是 `[B, 1, N]`，展开了行；`cumsum[:, :, None]` 是 `[B, N, 1]`，展开了列
- `[B, 1, N] <= [B, N, 1]` 的含义：token `j` 是否可以 attend token `i`，当且仅当 `cumsum[j] <= cumsum[i]`
- 结果：前 3 个 token 可以互相 attend（组 0），后 3 个 token 可以互相 attend（组 1），但后 3 个不能 attend 前 3 个（组 1 > 组 0 违反了 `<=` 条件）

```python
pad_2d_masks = pad_masks[:, None, :] * pad_masks[:, :, None]  # 双方都是 True 才有效
return att_2d_masks & pad_2d_masks
```

最终返回 `bool[B, N, N]`。

### 6. `compute_layer_complete` [L240-L308](file:///home/robot/projects/vla-advanced-algorithms/pytorch_learning/lerobot_source/lerobot/policies/pi0/modeling_pi0.py#L240-L308)

这是 `PaliGemmaWithExpertModel.forward` 模式 3 中每一层的具体计算。输入是一个包含两个元素的列表 `inputs_embeds = [prefix_emb, suffix_emb]`，以及该层配对的两个层 `layers = (paligemma_layer, expert_layer)`。

**第 1 步：LN + QKV 投影（对两个序列分别执行）**

```python
for i, hidden_states in enumerate(inputs_embeds):
    layer = layers[i]
    hidden_states, gate = layernorm_forward(layer.input_layernorm, hidden_states, adarms_cond[i])
```

先把 batch 中的每个 token 通过 LayerNorm（或在 Pi0.5 中是 adaRMS，接收 `adarms_cond[i]` 作为条件）。`gate` 是 RMS 的输出门控值，用于后续的 gated residual。

```python
    query_state = layer.self_attn.q_proj(hidden_states).view(hidden_shape).transpose(1, 2)
    key_state   = layer.self_attn.k_proj(hidden_states).view(hidden_shape).transpose(1, 2)
    value_state = layer.self_attn.v_proj(hidden_states).view(hidden_shape).transpose(1, 2)
```

`.view(hidden_shape).transpose(1, 2)` 把线性投影的输出从 `[B, seq, hidden]` 重塑为 `[B, num_heads, seq, head_dim]`。

**第 2 步：拼接 prefix 和 suffix 的 QKV**

```python
query_states  = torch.cat(query_states,  dim=2)   # dim=2 是 seq 维
key_states    = torch.cat(key_states,    dim=2)
value_states  = torch.cat(value_states,  dim=2)
```

如果 prefix 有 200 个 token，suffix 有 50 个 token，拼接后 seq 维是 `200+50=250`。head 维不变（分别来自两个模型）。

这里有一个关键设计选择：**prefix 的 QKV 来自 PaliGemma 的参数，suffix 的 QKV 来自 Action Expert 的参数。但它们被拼接到一起做联合注意力计算**。这意味着 prefix token（图像+语言）和 suffix token（带噪动作+时间）可以在注意力层中互相看到（取决于 attention mask 的限制）。

**第 3 步：旋转位置编码**

```python
cos, sin = rotary_emb(dummy_tensor, position_ids)
query_states, key_states = modeling_gemma.apply_rotary_pos_emb(
    query_states, key_states, cos, sin, unsqueeze_dim=1
)
```

`rotary_emb` 来自 PaliGemma 的 `language_model.rotary_emb`。`position_ids` 是从 padding mask 的 `cumsum - 1` 得到的连续位置编号。

**第 4 步：联合注意力计算**

```python
att_output, _ = modeling_gemma.eager_attention_forward(
    paligemma_layer.self_attn, query_states, key_states, value_states,
    attention_mask, scaling,
)
```

这里 `query_states` 和 `key_states` 都已经拼接了两个序列，attention mask 控制谁可以看谁。例如 suffix token 不能看未来的 suffix token（因果注意力），但可以看所有 prefix token。

**第 5 步：拆分回两个序列，各自输出投影**

```python
start_pos = 0
for i, hidden_states in enumerate(inputs_embeds):
    layer = layers[i]
    end_pos = start_pos + hidden_states.shape[1]
    out_emb = layer.self_attn.o_proj(att_output[:, start_pos:end_pos])
```

按原始 seq 长度切分 `att_output`，分别用各自层的 `o_proj`。

**第 6 步：第一个残差连接**

```python
out_emb = _gated_residual(hidden_states, out_emb, gates[i])
```

`_gated_residual` 是原始的 `hidden_states + gate * out_emb`。这里 `gate` 来自第一步的 RMS，`hidden_states` 是进入这一层前的原始 embedding。

**第 7 步：第二个 LN + MLP**

```python
after_first_residual = out_emb.clone()     # 保存第一次残差后的结果
out_emb, gate = layernorm_forward(layer.post_attention_layernorm, out_emb, adarms_cond[i])
out_emb = layer.mlp(out_emb)
```

标准的 Transformer 层：attention 输出 → LN → MLP。

**第 8 步：第二个残差连接**

```python
out_emb = _gated_residual(after_first_residual, out_emb, gate)
```

`after_first_residual` 不是 attention 输入，而是 attention 输出加第一个残差后的结果。

**第 9 步：返回两个 embedding**

```python
outputs_embeds.append(out_emb)
start_pos = end_pos
return outputs_embeds
```

输出仍然是 `[prefix_emb, suffix_emb]` 两个元素的列表，供下一层继续处理。

## 三、`to_bfloat16_for_selected_params` [L409-L430](file:///home/robot/projects/vla-advanced-algorithms/pytorch_learning/lerobot_source/lerobot/policies/pi0/modeling_pi0.py#L409-L430)

先把整个模型的参数全部转为 `bfloat16`。

```python
params_to_keep_float32 = [
    "vision_tower",           # SigLIP 视觉编码器
    "multi_modal_projector",  # 视觉特征投影到语言空间
```

## 1. 什么是隐藏宽度

隐藏宽度（hidden width，也叫 `hidden_size`）是：

> Transformer 内部用多少个浮点数表示一个 token。

它不是输入数据原本的特征数，也不是 Transformer 层数。

例如一句话经过 tokenizer：

```text
"pick red block"
    ↓
[token_1, token_2, token_3]
```

token 最初只是整数 ID：

```text
tokens.shape = [B, 3]
```

Embedding 层会把每个 token ID 查表转换成一个向量。假设隐藏宽度是 `2048`：

```text
tokens          [B, 3]
    ↓ Embedding
token embeddings [B, 3, 2048]
```

这里每个 token 都由 `2048` 个浮点数表示：

```text
token_1 → [0.17, -0.42, 0.08, ..., 0.31]  # 共 2048 个数
token_2 → [0.05,  0.21, ...]              # 共 2048 个数
token_3 → [...]                            # 共 2048 个数
```

Transformer 的每一层都会更新这些向量，但通常保持最后一维不变：

```text
第 1 层输入  [B, 3, 2048]
第 1 层输出  [B, 3, 2048]
第 2 层输出  [B, 3, 2048]
...
```

因此：

```text
隐藏宽度 = 每个 token 在模型内部的特征数量
```

### Pi0 中为什么有两个隐藏宽度

Pi0 有两个 Transformer：

```text
PaliGemma：   hidden width = 2048
Action Expert：hidden width = 1024
```

PaliGemma 的图像和语言 token 使用：

```text
prefix embedding [B, prefix_length, 2048]
```

Action Expert 的状态和动作 token 使用：

```text
suffix embedding [B, suffix_length, 1024]
```

两边各自使用自己的参数进行 Q、K、V 投影。Attention 会把它们投影成兼容的多头表示后进行联合计算；并不是直接把最后一维为 `2048` 和 `1024` 的 Tensor 原样拼接。

### 隐藏宽度与其他概念的区别

```text
hidden width = 2048  每个 token 有多少个内部特征
depth = 18           Transformer 有多少层
num_heads = 8        attention 分成多少个头
head_dim = 256       每个 attention head 有多少个特征
```

这里刚好：

```text
num_heads × head_dim = 8 × 256 = 2048
```

但 Action Expert 的 width 是 `1024`，其查询头总维度仍可能由具体 Attention 配置和投影决定，所以要以实现中的 Q/K/V shape 为准，后面读对应代码时再具体跟踪。

## 2. `dtype` 是什么意思

`dtype` 是 **data type（数据类型）**，表示 Tensor 中每个元素使用什么格式存储。

例如：

```python
x = torch.tensor([1.2, 3.4], dtype=torch.float32)
```

这里：

```text
x.dtype = torch.float32
```

常见 dtype：

| dtype | 含义 | 每个元素大小 |
|---|---|---:|
| `torch.float32` | 32 位浮点数 | 4 字节 |
| `torch.bfloat16` | 16 位脑浮点数 | 2 字节 |
| `torch.int64` | 64 位整数 | 8 字节 |
| `torch.bool` | 布尔值 | 通常 1 字节 |

dtype 会影响：

- Tensor 能表示什么数值
- 数值精度
- 显存占用
- GPU 计算速度
- 哪些运算可以一起执行

---

## 3. 配置里的 `dtype` 是输入观测数据类型吗

不是只指输入观测。

[配置中的 `dtype`](file:///home/robot/projects/vla-advanced-algorithms/pytorch_learning/lerobot_source/lerobot/policies/pi0/configuration_pi0.py#L33)主要控制：

> Pi0 模型的浮点参数和浮点计算采用 `float32` 还是 `bfloat16`。

例如模型中的 Linear 层有权重：

```text
weight.shape = [1024, 32]
```

如果配置为 `float32`：

```text
weight.dtype = torch.float32
```

如果配置为 `bfloat16`：

```text
weight.dtype = torch.bfloat16
```

相应的浮点输入通常也要转换为兼容的 dtype，否则矩阵乘法可能报错：

```text
输入 float32 @ 权重 bfloat16
```

某些操作不能直接混用这两种 dtype。

但是，**并非 batch 中所有 Tensor 都会转换为这个 dtype**。不同输入有不同职责。

### 图像

原始摄像头图像可能是：

```text
dtype = uint8
数值范围 = [0, 255]
shape = [B, C, H, W]
```

预处理后通常会转换为浮点数，并缩放数值：

```text
dtype = float32 或模型需要的浮点类型
数值范围 = [0, 1] 或 [-1, 1]
```

### 状态和动作

机器人状态和动作是连续数值：

```text
state.dtype  = float32 或 bfloat16
action.dtype = float32 或 bfloat16
```

它们参与 Linear、Flow Matching 和损失计算，因此必须使用浮点类型。

### 语言 token

token 是词表中的整数编号：

```text
language_tokens.dtype = int64
```

例如：

```text
"pick block" → [1, 2354, 8912, 2]
```

这些是 embedding 表的索引，不能转换成 `float32` 或 `bfloat16`。Embedding 查表需要整数 ID。

经过 Embedding 后，输出才变成浮点数：

```text
token IDs       [B, 48]       int64
    ↓ Embedding
token vectors   [B, 48, 2048] float32/bfloat16
```

### Attention mask

Mask 表示某个位置有效或无效：

```text
attention_mask.dtype = bool
```

或者某些接口使用整数/浮点 mask，但它并不是普通观测特征。

## 4. dtype 与 shape 的区别

这两个概念不要混淆。

假设：

```text
state.shape = [8, 32]
state.dtype = torch.float32
```

含义是：

- `shape=[8,32]`：有 8 个样本，每个样本有 32 个状态特征。
- `dtype=float32`：每个状态值使用 32 位浮点数保存。

同一个 shape 可以有不同 dtype：

```text
Tensor A：shape [8, 32]，dtype float32
Tensor B：shape [8, 32]，dtype bfloat16
```

它们包含相同数量的元素，但精度和内存占用不同：

```text
float32：  8 × 32 × 4 字节 = 1024 字节
bfloat16： 8 × 32 × 2 字节 = 512 字节
```

总结：

```text
hidden width
= Transformer 内部每个 token 的特征数量

dtype
= Tensor 每个元素的存储和计算类型

PI0Config.dtype
= 主要控制模型参数和浮点运算精度
≠ 所有原始观测都强制使用同一种类型
```

语言 token 仍是整数，mask 通常仍是布尔值，只有参与神经网络浮点运算的图像、状态、动作及内部 embedding 会使用相应的浮点 dtype。
